# 1. 게임

한국 토종 물고기 4마리가 오염된 강을 정화하는 **4인 협동 게임**이다.

```
목표    강 전체 오염도를 100% → 0%로 만든다
경로    상류 → 중류 → 하류를 지나며 구역별 정화 퀘스트를 수행한다
위협    포식자에게 쫓긴다. 플레이어는 공격 수단이 없고 회피만 한다
성장    작은 물고기(피식자)를 먹으면 허기가 차고 능력이 강해진다
```

> **"전투 없음"은 "공격 수단이 없다"는 뜻이지 "데미지가 없다"는 뜻이 아니다.**
> 피격·HP·행동 불능·자동 부활은 전부 있다. 방향이 한쪽일 뿐이다.

# 2. 핵심 루프

```
        탐색
          ↓
   피식자를 먹는다 ──▶ 허기 회복 + 성장 레벨 ↑
          ↓                      ↓
     포식자를 회피          능력 배율 ↑
          ↓                      ↓
   (맞으면 HP ↓)          정화가 더 빨라진다
   (허기 0이면 HP ↓)             ↓
          ↓                 오염도 ↓
  HP 0 → 15초 → 자동 부활         ↓
                          오염도 0% → 승리
```

**시스템 7개로 닫혀 있다.** 이 그림에 없는 것은 만들지 않는다.

# 3. 시스템 명세

각 절의 구성은 같다 — **규칙 / 서버가 정하는 것 / 미정**.

## 3.1 이동

플레이어 물고기는 WASD로 이동하고 마우스로 시점을 돌린다. 3인칭 시점.

### 규칙

- **클라 권위다**(2026-09-23). 소유 클라가 자기 물고기를 움직이고 `NetworkTransform`으로 보낸다.
- 남의 물고기는 **NT 보간**으로만 표시한다. 이동 코드를 다시 돌리지 않는다.
- **내 물고기만 Dynamic Rigidbody**(지형 충돌은 물리), 남의 물고기 · AI는 kinematic.
- 이동 계산은 `_Game/PlayerMotor` **한 곳에만** 있다.
- **서버는 플레이어 위치를 직접 쓰지 않는다.** 부활·넉백은 소유 클라에게 요청한다.

### 서버가 정하는 것

행동 불능(입력 잠금) 여부, 감속 단계, 부활 위치.
**거리 판정은 서버가 서버의 Transform으로 한다.** 그 좌표는 소유 클라가 보낸 값이라 늦으므로 허용오차를 둔다.

### 이동 계산에 들어가는 상태

**현재는 감속 디버프 하나뿐이다.** 성장·구역은 들어가지 않는다.
이동에 영향을 주는 서버 값은 **정수 단계로만** 두고 SyncVar로 보낸다. 소유 클라 Motor가 읽는다.

> 계약 전문은 [MOTION.md](MOTION.md). 이 절은 무엇을 만드는지만 정의한다.

### 미정

이동 속도·가속·선회 상한. 기획서의 "속도 20 / 가속도 50"은 **단위가 없어 그대로 쓰지 않는다.**

## 3.2 포식 — 허기와 성장

피식자(작은 물고기)에 다가가 **E를 누르면 먹는다.** 한 번에 **허기 회복 + 성장**이 동시에 일어난다.

### 규칙

- **허기는 0~10 정수 단계다.** 연속값을 동기화하지 않는다 (전송 방식은 [API.md](API.md) 5절).
- **허기가 0이면 HP가 계속 깎인다.**
- **회복 수단은 피식자 포식 하나뿐이다.**
- **성장하면 그 플레이어의 능력 배율만 오른다.** 남의 능력은 그대로다.
- **몸집은 커지지 않는다.** 따라서 성장은 이동 계산·충돌 반경에 영향이 없다.

### 서버가 정하는 것

포식 성공 여부, 허기 단계, 성장 레벨. **같은 피식자를 2명이 동시에 먹어도 1명만 성공한다.**

처리 순서는 고정이다:

```
검증 → 소비 선점 → 허기·성장 반영 → 연출 방송 → Despawn
        ↑ 반영보다 먼저 선점하므로 두 번째 요청이 실패한다
```

### 미정

허기 감소율, 포식 1회당 회복 단계 수, 허기 0일 때 HP 감소율,
성장 단계 수, 단계별 능력 배율, 사망 시 성장 유지 여부.

## 3.3 생존 — HP · 행동 불능 · 자동 부활

### 규칙

- 포식자에게 맞으면 HP가 깎인다. **플레이어는 반격할 수 없다.**
- **HP가 0이면 행동 불능**이다. 이동·포식·정화를 할 수 없다.
- **15초 뒤 서버가 자동으로 부활시킨다.**
- 행동 불능 중 소유 클라는 **입력을 잠근다.**
  부활은 순간이동이므로 서버가 소유 클라에게 요청하고, 소유 클라가 옮긴 뒤 **모든 관찰자의 보간 버퍼를 비운다.**
- **죽어도 오브젝트를 파괴하지 않는다.** 논리 상태는 Downed로 두고 표현만 사망 애니메이션이다.

### 서버가 정하는 것

HP, 피해 판정, 디버프, 행동 불능 여부, 부활 시각.
같은 공격의 다중 Collider 접촉은 `attackInstanceId + targetNetId`로 중복 제거한다.

### 실패 조건이 없다

**전원 사망 재시작은 폐기했다**(2026-09-21). 죽어도 15초 뒤 부활하므로 **게임은 승리로만 끝난다.**
페널티는 15초 정지와 그동안 정화를 못 하는 것이다.

> 4주차에 플레이해보고 밍밍하면 그때 조인다. **지금 미리 설계하지 않는다.**

### 미정

피해량, 디버프 종류·지속시간, 부활 시 HP 회복량(30% 제안), 부활 대기 시간(15초 제안).

## 3.4 포식자와 피식자

**둘 다 서버가 굴리는 AI다.** 클라의 AI 컴포넌트는 비활성화하고 애니메이션·보간만 실행한다.

| | 역할 | 모델 예 |
|---|---|---|
| 포식자 | 플레이어를 공격. 회피만 가능 | 메기, 쏘가리, 가물치 |
| 피식자 | 플레이어가 먹어서 허기 회복 + 성장 | — |

### 규칙

- **탐색·경로·난수·공격 쿨다운은 서버 전용**이다. 클라에는 위치와 표현 상태만 보낸다.
- **피식자는 컴포넌트 2개다** — 헤엄치는 AI + 먹히는 대상.
  Mirror는 하나의 `NetworkIdentity` 아래 여러 `NetworkBehaviour`를 허용한다.
- **판정용 난수는 서버에서만 굴린다.** 클라가 굴리면 4명이 다른 결과를 본다.
- 장식용 물고기는 로컬 전용이며 먹을 수 없다.

### 미정

추격·포획·해제 명세, 포식자 배치, **피식자 개체 수** — 전송량과 직결되므로 측정과 함께 정한다.

## 3.5 정화 — 오염도와 승리

기획서의 *"막혀 있는 돌을 부셔 물길을 뚫리게 한다"* 가 정화 퀘스트의 형태다.

### 규칙

- **붙어 있는 동안 진행도가 찬다.** 떨어지면 멈추고 진행도는 유지된다.
- 여러 명이 붙으면 **각자의 가중치가 합산**되어 빨라진다.
- **강화는 개인 것이고 공유되는 것은 결과다.**
  A가 1.5로 강화되고 B가 기본이면 둘이 붙었을 때 속도는 2.5다.
  A의 강화가 B의 기여율을 올리지 않는다.
- 목표가 완료되면 **전역 오염도**가 내려간다. **목표 진행도와 오염도는 별개 값**이다.
- **오염도 0%면 승리.** 판정은 서버가 한다.

### 서버가 정하는 것

진행도, 유효 기여자 집계, 완료 판정, 오염도.
완료는 **인스턴스 생애당 최대 1회**다.

### 형태가 하나뿐인 문제

정화가 이 한 형태뿐이면 **능력 4종이 전부 "진행바가 빨라진다"로 수렴한다.**
즉시형(E 한 번에 제거)을 추가할지는 **2주차 말 재검토 항목**이다 → [BACKLOG.md](BACKLOG.md)

### 미정

목표당 오염도 감소량, 진행도 유지/감소 정책, 즉시형 추가 여부.

## 3.6 능력 — 물고기 4종

플레이어 물고기는 **붕어 · 잉어 · 모래무지 · 참종개** 4종이며 각자 다른 능력을 갖는다.

### 규칙

- **능력은 전부 서버 판정이다.** 쿨다운·사용 조건·효과 적용을 서버가 정한다.
- 거부되면 **아무 상태도 바꾸지 않고 쿨다운도 갱신하지 않는다.**
- **강화 배율은 개인 것**이고, 공유되는 것은 그 결과다.

### 서버 판정 능력의 조건

```
그 결과가 나 말고 다른 사람 화면에도 보여야 한다

"정화를 더 빨리 진행한다"  → 서버 판정 ✅  진행바가 4명에게 같게 보인다
"위험을 먼저 감지한다"      → 로컬 표시 ❌  내 화면에만 아이콘
```

### 설계 제약: "없으면 못 함"이 아니라 "있으면 빠름"

특정 물고기가 있어야만 열리는 관문을 만들지 않는다.
**그 사람이 행동 불능이면 15초, 접속을 끊으면 영영 진행이 막힌다.**
재접속 복구는 범위 밖이라 복구 수단이 없다.

### ⚠️ 명세가 사실상 없다

기획서에 능력이 적힌 것은 **갈겨니의 "위험 조기 경보"** 하나뿐인데,
**갈겨니는 플레이어 물고기 목록에 없다.** 게다가 그 능력은 로컬 표시 형태라 서버 판정과 맞지 않는다.

**능력 4종 명세는 2주차 말 결정 항목 중 가장 급하다.** 4주차 전체가 여기에 걸려 있다.

## 3.7 구역

상류 · 중류 · 하류 3구역을 지난다.

### 규칙

- **1차 범위는 "지금 어느 구역인지"를 동기화해 HUD에 표시하는 것까지다.**
- **구역별 버프·이동 계수는 만들지 않는다.**
- 강 전체를 **하나의 씬**에 둔다. 구역은 논리 구역이며 이동 시 씬을 바꾸지 않는다.
- 경계에서 HUD가 깜빡이지 않도록 **히스테리시스**를 둔다.

### 왜 버프를 빼는가

버프는 **범위를 늘리는 기능 추가**라서 뺀다. 구역 판정 자체는 서버가 하고 표시만 한다.
나중에 넣는다면 연속값이 아니라 **구간 단계로 양자화**한 서버 값을 Motor가 읽게 한다.

### 미정

판정 기준(트리거 볼륨 vs 좌표 구간).

---

## 3.8 접속

- **호스트가 방을 열고, 참가자가 IP를 직접 입력한다.**
- 4인 고정. 5번째는 거부한다.
- **호스트가 나가면 세션 종료.** 마이그레이션 없음.
- 개발 테스트는 KCP + Tailscale. Steam은 3주차 이후 조건부.

**초대 코드와 무작위 방 매칭은 범위 밖이다.** 릴레이·로비 서버가 필요해 KCP 단독으로 불가능하고,
넣으려면 Steam 로비를 필수로 올려야 하는데 네트워크 담당 1명의 일정을 넘는다.

# 4. 권위 분배

**판단 기준 한 줄:** 이 값이 4명에게 같게 보여야 하면 서버가 정한다. 내 화면에만 보이면 클라가 정한다.

| 대상 | 결정 | 전달 방식 | 초기 주기 |
|---|---|---|---|
| 로컬 입력 | 소유 클라 | 전송하지 않는다 (Motor가 로컬에서 소비) | — |
| 플레이어 위치·회전 | **소유 클라** | ClientToServer `NetworkTransformReliable` (원격은 보간) | NT 기본 |
| 플레이어 상태 (Idle·Swim·Dash…) | 소유 클라 → **서버 검증** | Command → `State` SyncVar. Downed는 서버가 강제 | 변경 시 |
| 이동 계수 (감속 단계) | **서버** | 정수 SyncVar. 소유 클라 Motor가 읽음 | 변경 시 |
| 부활 순간이동 · 넉백 | **서버**가 요청 | 소유자에게 TargetRpc → 소유자가 이동 | 발생 시 |
| 포식자·피식자 위치 | **서버** | ServerToClient NetworkTransform | 10Hz |
| HP · 피격 · 디버프 | **서버** | 지속 상태 | 변경 시 |
| 허기 단계 (0~10) | **서버** | **정수 단계. 바뀔 때만** | 변경 시 |
| 행동 불능 · 자동 부활 | **서버** | 지속 상태 + 부활 완료 시각 | 변경 시 |
| 성장 단계 | **서버** | 정수 단계 | 변경 시 |
| 포식 성공 여부 | **서버** | 선점 후 Despawn | 변경 시 |
| 능력 사용 · 쿨다운 · 배율 | **서버** | 수락 응답 + 효과는 대상 상태로 | 변경 시 |
| 정화 진행도 | **서버** | 목표 상태 | 1Hz |
| 오염도 · 구역 · 승리 | **서버** | 세션 전역 상태 | 변경 시 |
| UI · 카메라 · 연출 | 각 클라 | 계약 이벤트 + 현재 상태 조회 | 로컬 |

> 주기는 **측정 전 시작값**이다. 측정 후 조정하고 결과를 테스트 기록에 남긴다.
> **계약(소유 클라 이동 · 원격 보간 · 서버 판정 · 서버의 소유자 경유 개입)은 조정 대상이 아니다.**

## 판정에 관한 절대 규칙

**모든 거리·범위 판정은 서버가 서버의 Transform으로 한다.**
**요청에 좌표를 실어 보내지 않는다.** 대상 ID만 보내고 서버가 자기 값으로 잰다.

서버의 플레이어 좌표는 소유 클라가 보낸 값이라 **늦다.** 그래서 허용오차를 둔다 —
플레이어가 판정하는 쪽(포식)은 넓히고, 판정당하는 쪽(피격)은 좁힌다. 수치는 [MOTION.md](MOTION.md) 5절.

> 좌표를 조작하면 이득을 볼 수 있다. **4인 협동 PvE라 감수한다**(2026-09-23). 비정상 이동은 로그만 남긴다.

# 5. 범위 경계

## 만든다

```
클라 권위 이동(NT) · 포식(허기+성장) · 포식자/피식자 AI
HP · 행동 불능 · 15초 자동 부활
정화 · 오염도 · 승리 · 구역 표시 · 능력 4종
```

## 후순위 — 설계는 보존, 여력 되면 착수

[BACKLOG.md](BACKLOG.md)에 설계·테스트·권위 행이 세트로 보관되어 있다.

| 순위 | 항목 | 이동 계산을 건드리나 |
|---|---|---|
| 1 | 새 (확률 공격) | 아니오 |
| 2 | 자원 채집 · 인벤토리 · 공유창고 | 아니오 |
| 3 | 건설 · 부화 · 산란/기지 | 아니오 |
| 4 | **낚시바늘 (구속·자성)** | **예 — Motor에 구속 모드 추가** |

**낚시바늘은 핵심 기획이지만 이동을 건드린다.** 그래서 P02에서 서버 → 소유자
`ApplyImpulse` 통로를 미리 만든다 — 나중에 Motor 구조를 다시 뜯지 않으려고.

## 제외 — 되살리려면 새 결정 필요

| 제외 | 대체 | 같이 사라진 것 |
|---|---|---|
| 동료 구조 | 15초 자동 부활 | `ReviveSession`, lease/heartbeat, 부활-피해 경합 |
| 전원 사망 재시작 | 없음 (실패 조건 자체가 없음) | `RoundCoordinator`, `roundEpoch`, 전체 초기화, Ready 타임아웃 |

## 범위 밖 — 논의하지 않는다

```
호스트 마이그레이션 · 재접속 복구 · 세이브/로드 · 전용 서버 빌드
완전한 안티치트 · 지연 보상(서버 되감기) · 5인 이상
초대 코드/무작위 매칭 · 구역별 버프
```

> **클라 예측·재조정은 만들지 않는다**(2026-09-23). 이동이 클라 권위라 필요가 없다.
>
> 안티치트 전체는 범위 밖이지만 **잘못된 수량·미등록 ID·요청 폭주 방어는 기본 구현에 포함한다.**
> 이동은 예외다 — 비정상 속도·순간이동은 **거부하지 않고 로그만** 남긴다.

# 6. 미정 항목 — 2주차 말까지 결정

**이 6개만 정하면 4주차까지 막히지 않는다.**

| 항목 | 결정할 것 | 막히는 곳 |
|---|---|---|
| **능력 4종** ⚠️ | 각 물고기의 능력 명세 (서버 판정 조건 충족) | 4주차 전체 |
| 성장 | 단계 수, 단계별 배율, 사망 시 유지 여부 | 2주차·4주차 |
| 허기 | 감소율, 회복 단계 수, 0일 때 HP 감소율 | 2주차 |
| 정화 | 목표당 감소량, 진행도 정책, 즉시형 추가 여부 | 3주차 |
| 구역 | 판정 기준 (트리거 볼륨 vs 좌표 구간) | 3주차 |
| 피식자 | 개체 수 — 전송량과 직결 | 2주차·5주차 |

**결정 전에 추측으로 구현하지 않는다.** 훅 시그니처만 열어 두고 정책은 나중에 채운다.

# 7. 기획서와 달라진 점

기획서를 읽은 팀원이 "이건 왜 없죠?"라고 물을 항목이다.

| 기획서에 있는데 | 어떻게 됐나 | 결정일 |
|---|---|---|
| 초대 코드 / 무작위 방 참가 (5쪽) | **범위 밖.** IP 직접 입력만 | 09-19 |
| 낚시 바늘 (4쪽) | **후순위.** 핵심이지만 이동 계산을 건드려 가장 비싸다 | 09-21 |
| 새 공격 (4쪽) | **후순위** | 09-21 |
| 먹이 = 미생물·수초·해초 (4쪽) | **피식자로 통합.** 포식 1회에 허기 + 성장 | 09-21 |
| 정화 = 수집품 모으기 (4쪽) | **붙어서 진행하는 형태로 변경.** 인벤토리가 후순위라 수집형 불가 | 09-21 |
| 크래프팅 · 기지 (5쪽) | **후순위** (보너스 목표) | 09-21 |
| 산란 지형 · 알 · 치어 (2·4쪽) | **후순위** (보너스 목표) | 09-21 |
| "주변의 동료를 도와준다" (5쪽) | **제외.** 15초 자동 부활로 대체 | 09-21 |
| "전원 행동 불능이면 재시작" (2쪽) | **제외.** 실패 조건 자체가 사라짐 | 09-21 |
| 갈겨니 (3쪽 능력 예시) | 플레이어 물고기 목록에 없음. 능력 명세 확정 시 정리 | — |
| 속도 20 / 가속도 50 (3쪽) | **단위가 없어 이동 상수로 쓰지 않는다.** 감각 튜닝으로 재설정 | — |
| 클라 권위 이동 (원문) | 09-18 서버 권위 + 예측·재조정으로 바꿨다가 **09-23 클라 권위 + NT로 복귀.** 예측·재조정이 1주차 일정 위험이라서 | 09-23 |
| 성장 시 몸집 변화 | **제외.** 능력 배율만 상승 | 09-19 |

## 왜 이만큼 뺐나

**기획 전량이 6주를 초과한다.** 네트워크 담당이 1명이고, 기능이 늘면 전부 그 1명에게 몰린다.

축소 효과:

```
베이스 클래스    5개 → 3개 (09-23 NetPlayerMotor 폐기)
기획 결정 항목  14개 → 6개
테스트 항목     32개 → 20개
난이도 2위였던 구속(Hooked)이 후순위로 이동
```

**남는 여력은 완성도(아트·연출·UI·사운드·레벨)에 쓴다.**
