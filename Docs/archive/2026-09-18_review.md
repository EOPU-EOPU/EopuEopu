2026-09-18 후속 변경: 사용자 결정에 따라 이동 권위를 클라 권위에서 **서버 권위 + 클라 예측·재조정·원격 보간**으로 바꾸고, 이를 **1주차 다인 테스트의 필수 진입 조건**으로 승격했다. 영향 문서: 권위 분배(계약 신설), API(4절 NetPlayerMotor 신설·이하 절 번호 이동), 결정(방향·범위·위험), 일정(1주차 작업·의존 순서), 테스트(T16~T20 및 게이트), 기획 적합성, 포트폴리오, 온보딩. 이 변경도 문서 수정이며 구현·검증을 의미하지 않는다.

## 외부 근거

공식 문서와 공개 소스를 대조했다. 프로젝트에 설치된 버전은 알 수 없으므로 최신 문서의 동작이 그대로 적용된다고 보장하지 않는다. 아래 설명은 요약이며 복사한 구현 코드는 없다.

1. [Mirror Remote Actions](https://mirror-networking.gitbook.io/docs/manual/guides/communications/remote-actions): Command 권한과 sender 전달, 클라 RPC 수신 구조 확인. 호출자 검증 및 결과/연출 경로 분리에 반영.
2. [Mirror SyncDictionary](https://mirror-networking.gitbook.io/docs/manual/guides/synchronization/syncdictionary): 구독 시 초기 데이터가 이미 존재하며 초기 항목은 별도 처리해야 함. UI 스냅샷 계약에 반영.
3. [Mirror Network Transform](https://mirror-networking.gitbook.io/docs/manual/components/network-transform): 방향 설정과 버전별 전송 설정을 확인. Hz를 확정 성능값으로 쓰지 않도록 수정.
4. [Mirror Multiplex](https://mirror-networking.gitbook.io/docs/manual/transports/multiplex-transport): 여러 트랜스포트 결합과 가용 트랜스포트 선택 설명. KCP·Steam 양쪽이 가용한 경우의 명시적 선택은 프로젝트 검증 항목으로 추가한 설계 판단.
5. [Mirror LatencySimulation 소스](https://raw.githubusercontent.com/MirrorNetworking/Mirror/master/Assets/Mirror/Transports/Latency/LatencySimulation.cs): latency 단위와 unreliableLoss 범위 확인. master는 가변 참조이므로 실제 프로젝트 버전으로 다시 확인해야 함.
6. [Unity 6 Rigidbody.MovePosition](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Rigidbody.MovePosition.html): kinematic 이동 및 FixedUpdate 사용 근거.
7. [Steamworks API Overview](https://partner.steamgames.com/doc/sdk/api): 초기화·App ID·개발 실행 환경을 확인해야 하므로 파일 하나로 연동 완료를 약속하지 않도록 수정.
8. [Mirror Client Side Prediction](https://mirror-networking.gitbook.io/docs/manual/general/client-side-prediction): 예측 관련 문서가 존재하므로 ‘라이브러리에 기능 없음’이라는 포괄적 주장을 제거. 서버 권위 이동 전환의 근거로도 사용했으나, 고정한 Mirror 버전에서 해당 기능을 그대로 쓸 수 있는지는 저장소에서 확인해야 한다. 본 문서의 NetPlayerMotor 계약은 특정 Mirror 예측 구현에 의존하지 않는 형태로 작성했다.
9. 스냅샷 보간(버퍼·보간 지연)은 Mirror 문서에 관련 설명이 있으나 이번 검토에서 해당 페이지를 직접 대조하지 않았다. 본 문서의 보간 계약은 일반적인 스냅샷 보간 설계이며, 고정한 Mirror 버전이 제공하는 기능·설정과 중복되거나 충돌하는지는 저장소에서 확인해야 한다.

## 2026-09-21에 새로 추가된 계약

이 항목들은 위 표에 없다. 범위 축소와 함께 들어왔다.

| 추가 | 왜 |
|---|---|
| **유실 틱 = 중립 입력으로 확정** | `seq`만으로는 "4번 유실, 5번 도착"에 답이 없어 서버·클라 궤적이 갈라진다 |
