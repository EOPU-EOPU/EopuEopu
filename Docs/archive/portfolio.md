# 포트폴리오 산출물

계획·구현·검증을 분리해 표현한다. 문서에 설계했다고 실제 구현·성능 개선을 완료한 것은 아니다.

| 산출물 | 필요한 증거 |
|---|---|
| 아키텍처·권위 분배 | 실제 asmdef 참조, 이동/서버 판정 경로, 본인 기여 커밋 |
| 서버 권위 이동·예측·보간 | 공유 Step 함수 코드, 재조정 발생·보정 거리 로그, 예측 on/off 비교 영상, T16~T19 결과 |
| 지연 비교 영상 | 동일 상황의 0/100/300ms 관측 RTT, 손실 설정, Host/Client 구분 |
| 전송량 그래프 | 동일 맵·인원·객체 수·이동 경로·빌드 조건, 측정 기간·단위 |
| 갱신 빈도 판단 | 실제 컴포넌트 설정과 체감/전송량 결과 |
| 디버그 HUD | 실제 수집 가능한 RTT·송수신량·역할 |

관심 영역 최적화(Interest Management)는 성능 문제가 관찰될 때 적용한다. 적용하면 전후 대역폭뿐 아니라 재관찰 시 상태 복원과 전역 세션 상태(오염도·구역) 전달도 검증한다. 효과가 작거나 비용이 더 크면 **채택하지 않은 근거도 결과다.**

**피식자 개체 수가 이 판단의 주 대상이다.** 무리로 배치하면 네트워크 오브젝트가 급증하므로,
개체 수를 정한 뒤 전송량을 측정하고 필요하면 5주차보다 앞당긴다(T32).

README에는 최대 4인·호스트 모드·호스트 종료 시 세션 종료·재접속 복구 미지원·실제 실행 절차·팀 역할·알려진 제한을 명시한다. 시연 영상과 실행 가능한 빌드를 함께 제공한다.

## 선택 산출물 — 참조 모델 검증

**Unity 없이 틱·입력·경합 로직만 떼어내 검증하는 방법**이다. 여력이 있으면 강한 소재가 된다.

```
독립 스크립트(Python 등)로 서버 틱 · 입력 큐 · 재조정 · 포식 경합을 모사한다
표준 라이브러리만 쓰고 엔진 의존을 없앤다

검증 항목 예:
  중복 / 누락 / 미래 입력       유효 미래 입력만 소비하는가
  축 이상값                     과대 moveDir이 거부되는가
  미처리 입력 재생              되감은 뒤 남은 입력만 재적용하는가
  포식 경쟁 · 재시도            둘이 동시에 먹어도 1명만 성공하는가
  보간 중복 / 역전 / 정지       시간이 뒤로 가지 않는가

무작위 시험:
  seed 0~99 · 세션당 180틱 · 손실 10% · 도착 지연 0~5틱 · 중복 주입 10%
  → 마지막 전체 스냅샷 적용 후 기준 상태가 일치하는가
```

**말할 때 구분해야 하는 것:**

> 이 모델은 **설계 계약이 논리적으로 성립하는지**를 확인한 것이지,
> 실제 RTT·조작감·3D 충돌·성능을 측정한 게 아니다.
> **"오류가 없다"가 아니라 "이 조건에서 이 불변식이 깨지지 않았다"** 로 말한다.

Unity 통합 시험(T16~T19)을 대체하지 않는다. **먼저 걸러내는 용도**다.

## 면접 설명의 기준

- Mirror 선택: 팀의 학습 자료·기존 경험·6주 일정에 맞춰 선택했다고 설명한다. 모든 대안보다 우월하다고 단정하지 않는다.
- 서버 권위 이동: 클라가 좌표가 아니라 입력을 보내고 서버 시뮬레이션 좌표로만 판정한다고 설명한다. 입력값 검증은 별개 문제이며 완전한 안티치트가 아니라는 점도 함께 말한다.
- 예측·재조정: 서버와 클라가 같은 결정론적 Step 함수를 쓰고, lastProcessedSeq로 확인된 입력을 버린 뒤 남은 입력을 재적용한다고 설명한다. 임계값·흡수 시간은 실제 측정으로 정한 값을 제시한다.
- 보간: 원격 표시는 서버시간에서 보간 지연만큼 뒤를 재생하며, 원격 복제본에서 이동을 재계산하지 않는다고 설명한다. 지연 보상(서버 되감기)은 구현하지 않았다고 구분해 답한다.
- 호스트 마이그레이션: 이번 프로젝트에서 구현하지 않았고 호스트 종료를 세션 종료로 정의했다고 답한다. 다른 라이브러리 전체의 지원 여부를 검증 없이 단정하지 않는다.
- 지연 대응: 실제 측정한 **포식자 회피와 포식(먹기) 체감**과 조정 내용을 제시한다. 히트박스를 넓혀 문제가 해결됐다고 측정 전 주장하지 않는다.
- 범위 축소: 기능을 뺀 것을 실패가 아니라 **일정 판단**으로 설명한다. 무엇을 왜 뺐고(6주/네트워크 담당 1명), 나중에 넣을 수 있도록 무엇을 남겼는지(`MoveConfig` 외력 슬롯, `MotionEpoch`, `Docs/BACKLOG.md`) 함께 말한다. **뺀 항목의 설계를 보존해 뒀다는 점이 근거다.**
- 자동 부활: 동료 구조 대신 자동 부활을 고른 이유(6주 일정, `ReviveSession`·lease 복잡도)와, 그래도 지켜야 했던 것(`MotionEpoch`로 부활 직후 위치 튐 방지)을 구분해 설명한다.
- 인계: 실제로 구현한 계약과 컴파일 경계를 보여준다. _Local의 Mirror 차단은 asmdef 참조·코드로 확인한 뒤 성과로 쓴다.
- 가장 어려웠던 문제: 재현 조건·원인·수정·회귀 증거가 있는 실제 사례를 사용한다.
