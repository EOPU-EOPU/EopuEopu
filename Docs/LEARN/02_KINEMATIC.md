# 왜 내 물고기는 Dynamic이고 남의 물고기는 Kinematic인가

**대상:** `_Game/` 담당자 전원
**한 줄 요약:** 내 물고기는 싱글 게임처럼 물리로 움직이고, 남의 물고기는 NT가 받은 위치를 그대로 그려야 하니 물리를 끈다.

> **변경 이력.** 09-18 설계는 서버 권위 + 예측이라 모든 물고기가 kinematic이어야 했다(결정론 때문).
> 09-23에 이동이 **클라 권위**로 바뀌면서 그 이유가 사라졌고, **소유자는 Dynamic**으로 바꿨다.
> 설정값과 규칙의 정본은 [MOTION.md](../MOTION.md) 1.1절이다. 이 문서는 *왜*만 설명한다.

## 같은 프리팹, 같은 코드 — 체크박스 하나만 다르다

```
Player 프리팹 (하나)
├── NetworkTransform
├── Rigidbody          ← 스폰 시 isKinematic 값만 정해 줌
└── PlayerMotor        ← 이동 로직. 하나뿐
```

| | 내 PC의 내 물고기 | 내 PC의 남의 물고기 |
|---|---|---|
| Rigidbody | Dynamic | Kinematic |
| `PlayerMotor` | 돈다 | 꺼져 있다 |
| 위치 | Motor + 물리가 정함 | NT가 받은 위치를 씀 |

**Kinematic 버전 이동 로직을 따로 만드는 게 아니다.** 남의 물고기는 이동 로직을 아예 안 돌린다.
kinematic은 "NT가 Transform에 쓰는 동안 물리 엔진이 끼어들지 마라"는 설정일 뿐이다.

B의 PC에서는 반대로 B의 물고기가 Dynamic, 내 물고기가 Kinematic이다.

---

## 왜 내 물고기는 Dynamic인가

**지형 충돌을 물리가 공짜로 해 준다.**

kinematic으로 하면 벽에 부딪혀 미끄러지는 처리(collide-and-slide)를 직접 짜야 한다 —
`SphereCast`로 막힌 방향 성분을 빼고, 파고들면 밀어내고, 모서리에서 끼이지 않게 여러 번 반복한다.
바위·강바닥이 많은 맵에서 **벽 관통 버그가 가장 많이 나는 곳**이다.

클라 권위라 이동을 서버와 똑같이 재현할 필요가 없으니, 물리가 PC마다 조금 다르게 계산해도 문제없다.

그 밖에:
- 물의 관성·저항은 `linearDamping` · `mass`로 바로 표현된다
- 넉백·유속은 `AddForce`로 자연스럽게 들어간다

## 왜 남의 물고기는 Kinematic인가

NT가 받은 위치를 Transform에 직접 쓴다. Dynamic이면 물리 엔진도 매 프레임 Transform을 옮긴다.

```
NT:     "여기 있어야 해"
물리:   "충돌 때문에 저기로 가야 해"
→ 둘이 번갈아 이겨서 떨린다
```

**프리팹 기본값은 kinematic**이고, 소유 권한을 받은 순간 소유자만 Dynamic으로 바꾼다.
기본값이 Dynamic이면 권한 정보가 도착하기 전 몇 프레임 동안 남의 물고기가 물리로 움직인다.

## 포식자 · 피식자는 전부 Kinematic

서버 AI가 목표를 향해 옮기는 구조라 물리가 필요 없다. 클라에서는 NT 보간만 한다 → [API.md](../API.md) 2절

## 싱글과 다른 점은 딱 하나의 원칙에서 나온다

> **내 PC의 물리는 내 화면만 움직인다. 게임 결과는 서버가 정한다.**

그래서 `OnCollisionEnter`로 HP를 깎지 않고, 플레이어끼리·플레이어와 AI 사이의 물리 충돌은 끈다.
구체적인 설정값(회전 고정·연속 충돌 감지·보간·충돌 레이어)과 자주 밟는 증상은 [MOTION.md](../MOTION.md) 1.1 · 2 · 7절에 있다.
