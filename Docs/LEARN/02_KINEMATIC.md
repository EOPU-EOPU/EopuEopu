# 왜 Kinematic인가

**대상:** `_Game/` 담당자 전원
**한 줄 요약:** Dynamic(AddForce)은 PC마다 결과가 달라서, 서버와 클라가 같은 계산을 재현할 수 없다.

---

## 먼저: 이건 여러분이 매일 만질 코드가 아닙니다

플레이어 이동 코드는 `_Net/`의 `MoveStep` 한 곳에만 있고, 네트워크 담당이 씁니다.
여러분이 하는 일은 **속도·가속·유속·선회 수치를 제안하고 튜닝**하는 것입니다.

이 문서는 "왜 익숙한 `AddForce`를 안 쓰는지" 납득하고,
**포식자·바늘 같은 움직이는 오브젝트를 만들 때 같은 규칙을 지키기 위한** 것입니다.

---

## 이유 1 — 물리 결과는 PC마다 다르다

Unity 물리(PhysX)는 같은 입력이라도 **PC·프레임 타이밍이 다르면 다른 결과**를 냅니다.

우리 구조는 이렇습니다:

```
클라: 입력을 서버에 보내고, 동시에 로컬에서도 미리 계산해서 즉시 움직인다  (예측)
서버: 진짜 위치를 계산해서 내려보낸다
클라: 내 예측과 서버 결과가 다르면 되감아서 다시 맞춘다                    (재조정)
```

**예측이 성립하려면 "서버와 클라가 같은 계산을 하면 같은 결과가 나온다"가 참이어야 합니다.**
`AddForce`를 쓰면 이 전제가 깨집니다. 매 프레임 조금씩 어긋나고, 캐릭터가 계속 튑니다.

## 이유 2 — 되감기가 물리 엔진에서는 불가능하다

재조정은 "서버 위치로 되돌린 뒤 내 입력을 다시 적용"입니다. Dynamic으로 하려면:

- `Physics.Simulate()`를 여러 번 호출해야 하는데 이건 **씬 전체**가 같이 움직입니다.
  물고기 하나 되감으려고 강·포식자·바늘·자원노드가 전부 딸려 갑니다.
- PhysX 내부 상태(접촉, 관통 깊이, sleep 여부)는 **저장·복원하는 API가 없습니다.**

이건 Mirror의 한계가 아니라 **Unity 물리 엔진 자체의 한계**입니다. 다른 네트워크 라이브러리로 바꿔도 같습니다.

## 이유 3 — 서버가 위치를 강제할 때 4대가 전부 다르게 보인다

**내 입력과 무관하게 서버가 내 위치를 정하는 구간**이 있습니다.
지금은 **행동 불능(HP 0)과 자동 부활**이 그렇고,
후순위인 **낚시바늘에 끌려가는 구간**도 같은 종류입니다.

Dynamic이면 서버가 위치를 정하는 동안 클라의 물리도 따로 돌면서 서로 싸웁니다.
그 내내 진동하고, 4명이 서로 다른 그림을 봅니다.

Kinematic이면 **"이 구간은 서버가 준 위치만 그린다"** 로 깔끔하게 전환됩니다.
예측을 끄고 보간 표시로 넘어갔다가, 풀리면 버퍼를 비우고 다시 예측을 켜는 식입니다.

## 이유 4 — 이 게임은 Dynamic이 필요 없다

Dynamic의 진짜 장점은 **밀고, 쌓이고, 튕기는 창발적 반응**입니다.
우리 게임에는 전투도, 래그돌도, 물체 밀기도, 쌓기도 없습니다.

즉 **대가만 치르고 효용은 안 받습니다.**
물속 부력·저항·유속은 직접 계산하는 게 오히려 더 쉽고 예측 가능합니다.

---

## 그래서 어떻게 쓰나 — 변환표

익숙한 Dynamic 코드의 등가는 전부 있습니다. 어렵지 않습니다.

| 익숙한 Dynamic | Kinematic 등가 |
|---|---|
| `rb.AddForce(dir * f)` | `vel += dir * accel * dt` |
| `rb.AddForce(dir * f, ForceMode.Impulse)` | `vel += dir * impulse / mass` |
| `rb.drag = d` | `vel *= Mathf.Exp(-d * dt)` |
| `rb.velocity = v` | `vel = v` (우리가 들고 있는 필드) |
| `useGravity` | `vel.y -= g * dt` (물속이면 부력과 상쇄되어 보통 0) |
| 자동 충돌 반사 | `vel -= Vector3.Project(vel, hit.normal)` |
| 적용 | `rb.MovePosition(pos + vel * dt)` — `FixedUpdate`에서 |

Rigidbody 설정: `isKinematic = true`, `useGravity = false`, `interpolation = None`

## 주의할 점 하나 — 충돌 감지 방식이 다릅니다

**Kinematic Rigidbody는 벽·바닥 같은 static 콜라이더와 부딪혀도 `OnCollisionEnter`가 오지 않습니다.**
(Unity 충돌 매트릭스상 한쪽은 non-kinematic이어야 이벤트가 발생합니다.)

- **지형 충돌** → 이동 계산 안에서 `Physics.SphereCast`로 직접 확인
- **채집·상호작용 판정** → 트리거는 kinematic에서도 **정상 동작**하므로 그대로 사용

여기서 한 번씩 막힙니다. 미리 알아두시면 됩니다.

---

## 포식자·바늘도 같은 규칙입니다

- `NetServerAI`의 `Think()`는 **목표만** 정하고, 실제 이동은 베이스가 합니다.
- `MoveTo`는 "목표 위치 + 초당 속도"를 저장하는 함수입니다. 한 걸음 옮기는 함수가 아닙니다.
- **남의 캐릭터·포식자·바늘은 서버가 준 위치를 보간해서 그릴 뿐, 이동 계산을 다시 돌리지 않습니다.**
